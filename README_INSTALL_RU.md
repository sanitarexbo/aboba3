# Finesse CRM 4.0 — React + TypeScript + Node.js

Версия с реальными аккаунтами, единым сервером и SQLite. **Python не используется.**

## Что внутри

- **Frontend:** React 19, TypeScript, Vite; три темы; оригинальные белый и чёрный логотипы Finesse.
- **Backend:** Node.js 22.16+ / 24 LTS, TypeScript, встроенный `node:sqlite`, встроенный HTTP-сервер. Не требует Express/Python.
- **DB:** SQLite в режиме WAL; схема совместима с серверной Python-версией Finesse (можно перенести старый `.sqlite3`).
- **Авторизация:** email + пароль, scrypt, HttpOnly cookie, CSRF, ограничение попыток входа, одобрение нового аккаунта владельцем/администратором.
- **Разделы:** обзор, смены, текстовые чаты участников, отчёты, пять площадок, подтверждение и начисления, аналитика, сотрудники, команды, KPI, отгулы, обучение, штрафы, уведомления, балансы, заявки на выплаты, настройки, журнал действий.
- **Отключено:** любые аудио-/видеозвонки, записи звонков, архив звонков.
- **Важно:** выплата в CRM фиксируется статусом; реальные банковские переводы автоматически не выполняются. Полные номера карт хранить нельзя.

## 1. Подготовка VPS

Рекомендуется Ubuntu 24.04 LTS с публичным IPv4, не менее **2 vCPU, 2 ГБ RAM, 30 ГБ SSD** для небольшой команды. На 2 ГБ может потребоваться 1 ГБ swap при сборке фронтенда. Для большой команды лучше 4 ГБ RAM.

Если подключаетесь к VPS по SSH, держите терминал открытым до завершения сетевых настроек и **не блокируйте порт SSH**.

DNS: у регистратора создайте A-запись `crm` на IP-адрес VPS, если выбран домен `crm.example.com`. Если используете корневой домен, создайте A-запись `@`. Для пользователей в России и Украине начните без Cloudflare Proxy и проверьте доступ с нужных сетей. SSL не гарантирует доступность у каждого оператора связи.

## 2. Скопировать проект

**На своём компьютере:**

```bash
scp Finesse_CRM_React_TS.zip root@IP_СЕРВЕРА:/root/
```

**На сервере:**

```bash
sudo apt-get update
sudo apt-get install -y unzip
cd /root
unzip Finesse_CRM_React_TS.zip
cd Finesse_CRM_React_TS
```

Если на сервере вы не под `root`, скопируйте ZIP в домашнюю папку пользователя, затем переходите в распакованную папку.

## 3. Установить Node.js, приложение, systemd и Nginx

```bash
sudo bash deploy/install.sh crm.example.com
```

Замените `crm.example.com` на ваш домен. Скрипт установит Node.js (если нужна подходящая версия), Nginx, Certbot, React-зависимости, соберёт приложение (`npm run build`), создаст системного пользователя `finesse`, сервис systemd и ежедневные резервные копии. Он **не открывает порты SSH или не меняет UFW автоматически**.

Проверьте:

```bash
sudo systemctl status finesse-crm --no-pager
curl http://127.0.0.1:8080/health
```

Должно вернуться `{"ok":true,"service":"finesse-crm-node"}`.

### Если на VPS 2 ГБ RAM и не хватает памяти при npm build

Можно временно создать swap (перед этим проверьте свободное место на диске):

```bash
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

Включение swap переживает только текущую перезагрузку, если не добавлена запись в `/etc/fstab`. На небольшом VPS при использовании больших сборок может быть лучше собирать React на компьютере и загружать каталог `dist`.

## 4. Открыть доступ в брандмауэре

**Прежде чем включать UFW, посмотрите текущий SSH-порт:**

```bash
sudo ss -tlnp | grep sshd
```

Если порт SSH 22:

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

Если SSH работает на другом порту, разрешите **его**, а не 22. Панель AlphaVPS также может иметь собственные сетевые правила.

Порт 8080 снаружи **не открывайте** — на нём Node слушает `127.0.0.1`, а наружу доступ только через Nginx.

## 5. Включить HTTPS

Убедитесь, что DNS A-запись указывает на VPS, а HTTP-порт 80 доступен из интернета. Затем:

```bash
sudo certbot --nginx -d crm.example.com --redirect
```

Проверьте обновление:

```bash
sudo certbot renew --dry-run
```

Откройте `https://crm.example.com`.

## 6. Создать первого владельца

```bash
sudo bash /opt/finesse-crm/deploy/create-owner.sh
```

Скрипт спросит email, имя и пароль от 12 символов (пароль вводится без отображения). На странице входа войдите как владелец. **Самостоятельная регистрация создаёт аккаунт стажёра, который требует одобрения**.

Далее владелец в разделе **Сотрудники** подтверждает заявки и назначает роли. Рекомендуется перед реальным использованием создавать отдельные аккаунты для каждого сотрудника и не делиться паролями.

## 7. Рабочий сценарий

1. Владелец создаёт команды, выбирает тимлида и коуча; назначает модели и операторов.
2. Оператор создаёт смену и находит модель по email/никнейму. Поле площадки у смены отсутствует.
3. В карточке смены можно писать текстовые сообщения, видимые другому участнику.
4. Оператор создаёт отчёт, при необходимости выбирает **Связанную смену**, вводит суммы в USD для пяти площадок. Общая сумма рассчитывается автоматически.
5. Тимлид своей команды либо администратор проверяет отчёт. **До одобрения начислений нет**.
6. После одобрения начисления рассчитываются на сервере и попадают в балансы, при этом проценты **не возвращаются в браузер**.
7. У модели главная показывает только заработок по сменам, без площадок.
8. Отгулы, штрафы, KPI, обучение, выплаты и уведомления работают через общую SQLite-базу.

## 8. Backup и восстановление

Проверить таймер:

```bash
sudo systemctl list-timers finesse-backup.timer
sudo systemctl start finesse-backup.service
sudo ls -l /var/lib/finesse-crm/backups
```

Бэкап делается SQLite Online Backup API и не требует остановки сайта. Хранятся последние 14 резервных копий в папке VPS. **Обязательно делайте дополнительные копии вне сервера**, иначе потеря VPS приведёт к потере всех локальных бэкапов.

Восстановление (пример; используйте только после проверки выбранного файла):

```bash
sudo systemctl stop finesse-crm
sudo cp /var/lib/finesse-crm/finesse.sqlite3 /var/lib/finesse-crm/finesse.sqlite3.before-restore
sudo cp /var/lib/finesse-crm/backups/ИМЯ_ФАЙЛА.sqlite3 /var/lib/finesse-crm/finesse.sqlite3
sudo chown finesse:finesse /var/lib/finesse-crm/finesse.sqlite3
sudo systemctl start finesse-crm
```

Восстановление требует отсутствия активных соединений со старой базой. Если есть `.sqlite3-wal`/`.sqlite3-shm` от старого процесса, обратитесь к инструкции SQLite о консистентном восстановлении; **не копируйте WAL поверх резервной копии**.

## 9. Если раньше стояла Python-версия Finesse

**Перед обновлением сделайте резервную копию**. Остановите старый сервис Python, затем перенесите **полный файл SQLite** из старой `FINESSE_DB` в `/var/lib/finesse-crm/finesse.sqlite3` с владельцем `finesse:finesse`. Старые пароли scrypt и таблицы совместимы. Если старая база работала в режиме WAL, остановите Python-сервис и убедитесь, что данные зафиксированы (выполнен checkpoint), затем используйте онлайн-бэкап SQLite. Не копируйте активную SQLite-базу обычной командой `cp`.

Новый сайт не использует Python. Перенос данных из **старого HTML-прототипа localStorage** автоматически не поддерживается (его данные не находятся в SQLite).

## 10. Обновление проекта

```bash
cd /root/Finesse_CRM_React_TS
# Загрузите сюда новые файлы проекта перед обновлением
sudo systemctl start finesse-backup.service
sudo bash deploy/install.sh crm.example.com
```

Старую базу в `/var/lib/finesse-crm` установщик не удаляет. Проверьте права, новые роли и отчёты перед обновлением рабочего сервера.

## 11. Тесты и диагностика

```bash
npm run test:api
sudo journalctl -u finesse-crm -n 120 --no-pager
sudo nginx -t
sudo systemctl status finesse-crm --no-pager
curl https://crm.example.com/health
```

`npm run test:api` поднимает отдельную временную базу и тестовый сервер, **не затрагивает рабочую SQLite**.

## 12. Важные ограничения перед запуском с настоящими деньгами

- Проект предназначен для небольшой команды на одном VPS. Проведите независимую проверку безопасности, нагрузки и резервного восстановления перед использованием реальных финансовых и персональных данных.
- Учет в USD; RUB — только отображение по заданному администратором условному курсу. Реального валютного обмена нет.
- Владелец и администратор вручную подтверждают/отмечают выплаты; фактических переводов денег код не выполняет.
- Никаких аудиозвонков, видеозвонков, записи разговоров и архива записей в версии нет.
- Оповещения появляются внутри CRM (проверка примерно раз в 30 секунд). Push-уведомления в операционной системе не реализованы.
- Для большого количества пользователей, хранения файлов и нескольких серверов лучше перейти с SQLite на PostgreSQL с миграциями и отдельным хранилищем вложений.
- Если VPS/провайдер недоступен из какой-либо страны, TLS и Nginx этого не исправят: проверяйте подключение через реальных провайдеров.
